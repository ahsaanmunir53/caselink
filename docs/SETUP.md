# Setting up CaseLink

Everything here runs on free plans. Keys and passwords go in `backend/.env` on your computer, or in Render's Environment settings, never in code, chat or Git.

## 1. Run it on your computer

You need Python 3.12 and Node 22.

```
cd backend
python -m venv .venv
.venv\Scripts\activate                 # macOS/Linux: source .venv/bin/activate
pip install -r requirements-dev.txt
copy .env.example .env                  # macOS/Linux: cp .env.example .env
python run.py
```

The API is at http://127.0.0.1:8000 (`/api/health` should say `"status": "ok"`). On first start it loads the 275 synthetic reports and links them, which takes a few seconds.

In a second terminal:

```
cd frontend
npm install
npm run dev
```

Open http://localhost:5173. The dev server forwards `/api` to port 8000, so `VITE_API_URL` can stay empty.

To try the analyst workflow, choose **Sign in** and pick Ayesha. Open the top proposed case, choose **Start the review**, then **Approve the case**. Sign in as Bilal to confirm it (the four-eyes rule), move it to investigating, then referred, and download the STIX bundle or prepare the referral.

### Tests and evaluation

```
cd backend
pytest -q
ruff check app tests eval
python -m eval.run_eval          # writes eval/results.md and eval/results.json
python -m eval.gate              # fails if the numbers dropped below eval/thresholds.json
python -m eval.run_eval --with-ai   # also asks the AI for a second opinion on every suggestion (needs a key)
```

## 2. AI keys (optional, free)

Without keys, summaries come from a template, the assistant answers with search results, and translation is switched off. Everything else works.

| Key | Where to get it | What it does |
|---|---|---|
| `GROQ_API_KEY` | https://console.groq.com/keys | Main models: `openai/gpt-oss-120b`, then `openai/gpt-oss-20b`. |
| `GOOGLE_API_KEY` | https://aistudio.google.com/apikey | Gemini, used when Groq is rate-limited or down. |

You can use the same keys as Hoshiyar; the free limits are shared between the two apps. At start-up CaseLink asks each provider which models are live and skips retired ones, so a model that Groq retires does not break it. `GET /api/health/ai` pings each model and shows which ones answer.

## 3. Postgres on Neon (optional locally, needed on Render)

SQLite is used when `DATABASE_URL` is empty. Render's free disk is wiped on every deploy, so the hosted version needs Postgres.

1. In the Neon console create a **new project** called `caselink`. Keep it separate from Hoshiyar's project so the demo reset never touches Hoshiyar's data.
2. On the project dashboard choose **Connect**, switch **Connection pooling off**, and copy the connection string. It looks like `postgresql://user:password@ep-something.region.aws.neon.tech/neondb?sslmode=require`.
3. Paste it as `DATABASE_URL` on one line, with no space or line break at the end.

If you paste the `-pooler` host anyway, CaseLink switches to the direct host by itself and says so in the log (LangGraph's checkpointer needs a direct connection). Tables are created on the first start.

## 4. Deploy to Render

The repository has a Blueprint (`render.yaml`) for two services: `caselink-api` (free web service) and `caselink-web` (free static site).

1. Push the repository to GitHub.
2. In Render choose **New**, then **Blueprint**, and pick the repository.
3. Render asks for the values marked `sync: false`:

| Service | Key | Value |
|---|---|---|
| caselink-api | `DATABASE_URL` | the Neon string from step 3 |
| caselink-api | `GROQ_API_KEY`, `GOOGLE_API_KEY` | your keys, or empty |
| caselink-api | `ALLOWED_ORIGINS` | `https://caselink-web.onrender.com` (no slash at the end) |
| caselink-api | `PUBLIC_APP_URL` | `https://caselink-web.onrender.com` |
| caselink-api | `ADMIN_EMAIL`, `ADMIN_PASSWORD` | optional, your own login |
| caselink-api | `HOSHIYAR_API_URL`, `HOSHIYAR_INTEGRATION_KEY` | optional, see [HOSHIYAR.md](HOSHIYAR.md) |
| caselink-api | `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ALERT_CHAT_ID` | optional, for the daily digest |
| caselink-web | `VITE_API_URL` | `https://caselink-api.onrender.com` |

`AUTH_SECRET` and `CRON_SECRET` are generated by Render. If Render adds a suffix to a service name (for example `caselink-api-x7k2`), put the real URLs into `VITE_API_URL`, `ALLOWED_ORIGINS` and `PUBLIC_APP_URL`, then redeploy both services. `VITE_API_URL` is read when the site is built, so the static site needs a redeploy after it changes.

4. When both are live, open `https://caselink-api.onrender.com/api/health`, then the site.

The free API sleeps after 15 minutes without traffic and takes about a minute to wake. The site shows a notice while it waits. The static site never sleeps.

## 5. GitHub Actions

Three workflows are included:

| Workflow | What it does |
|---|---|
| `ci.yml` | Lint, tests, the evaluation and the quality gate on every push; builds the frontend. |
| `keep-warm.yml` | Pings the API every 10 minutes in Singapore office hours on weekdays, so a reviewer does not wait for it to wake. |
| `scheduled-jobs.yml` | Resets the public demo every night, and sends the digest to Telegram on weekday mornings. |

In the repository's **Settings**, **Secrets and variables**, **Actions**:

- Variables: `BACKEND_URL` = `https://caselink-api.onrender.com`
- Secrets: `CRON_SECRET` = the value Render generated for `caselink-api` (Environment tab)

Render's 750 free instance hours a month are shared by every free service in a workspace. Keep-warm on both CaseLink and Hoshiyar uses roughly 420 of them; switch one off if you need the hours elsewhere.

## 6. The MCP server (optional)

Lets an AI assistant query the cases, read-only. It runs on your computer and calls the API.

```
cd backend
.venv\Scripts\activate
set CASELINK_API_URL=https://caselink-api.onrender.com
python app/mcp_server.py
```

For Claude Desktop, add to `claude_desktop_config.json`:

```json
{"mcpServers": {"caselink": {
  "command": "D:\\path\\to\\caselink\\backend\\.venv\\Scripts\\python.exe",
  "args": ["D:\\path\\to\\caselink\\backend\\app\\mcp_server.py"],
  "env": {"CASELINK_API_URL": "https://caselink-api.onrender.com"}}}}
```

Tools: `list_cases`, `get_case`, `search_reports`, `ask`.

## 7. Settings worth knowing

| Setting | Default | Meaning |
|---|---|---|
| `DEMO_MODE` | `true` | Open reading and one-click demo logins. Set `false` for anything but synthetic data. |
| `FOUR_EYES` | `true` | A second person confirms before a case is referred or exported. |
| `SEED_SYNTHETIC_DATA` | `true` | Load the synthetic reports into an empty database. |
| `HUB_SHARE`, `HUB_MIN_REPORTS` | `0.08`, `12` | An identifier in more reports than this is treated as common and links nothing on its own. |
| `NAME_MIN_LENGTH` | `5` | Shorter agency names only link as common names. |

## Troubleshooting

| What you see | Fix |
|---|---|
| The site loads but every page says the server could not be reached | `ALLOWED_ORIGINS` on the API must be the site's exact URL, with `https://` and no slash at the end. Redeploy the API after changing it. |
| Deploy log: `password authentication failed` or `could not translate host name` | `DATABASE_URL` is incomplete. Copy it again from Neon's Connect dialog, including the password. (Spaces and line breaks from pasting are removed automatically.) |
| Logins say "Set AUTH_SECRET" | The API is in production or on Postgres without a strong `AUTH_SECRET`. Render generates one from the Blueprint; set one by hand if you created the service yourself. |
| First page takes a minute | The free API was asleep. Turn on the keep-warm workflow. |
| Summaries read like a template | No AI model answered. Check `/api/health/ai`. |
